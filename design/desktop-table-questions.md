# Desktop tables: reader questions

Written after viewing the current 1440px queue, before opening its source.

1. Which requests need my attention, and what should I do next on each?
2. Which requester, agency, and coordinator belong to each request?
3. Which requests have waited longest, carry greater risk, or have higher human-entered priority?
4. How can I narrow or reorder the complete set without losing my place?
5. Can I open a request or its priority estimates directly, and recover if a list update fails?

Keep those answers together in a readable desktop table. Remove custom scrolling buttons and pagination for 100 or fewer matches. Keep supporting identifiers and counting bases quieter than request titles and next actions. Mouse clicks must not draw focus boxes; keyboard focus must remain visible. Show the active sort arrow intact beside its heading.
